# LR-05: Add a CRM delivery adapter and redacted failure alerts

## Goal / Context

Provide a vendor-neutral CRM transport and operational failure notification. Select the real vendor only through explicit configuration and its API contract.

## Exact Files to Touch

- `services/lead-router/src/adapters/crm.ts` (add)
- `services/lead-router/src/alerts.ts` (add)
- `services/lead-router/src/server.ts`
- `tests/integration/crm.test.ts` (add)
- `.env.example`

## Concrete Acceptance Criteria

- [ ] Require an HTTPS allowlisted CRM URL, server credential and remote idempotency key.
- [ ] Separate retryable network/429/5xx failures from permanent validation/authentication failures.
- [ ] Alerts include event ID, status category and counts, excluding phone/name/body/token.
- [ ] Keep connectors disabled unless all required configuration is valid.
- [ ] Fake-transport tests cover delivery, duplicate request, timeout and redaction.

