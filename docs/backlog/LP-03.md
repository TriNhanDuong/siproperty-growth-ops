# LP-03: Establish measurable performance and accessibility budgets for campaign pages

## Goal / Context

Create a repeatable Lighthouse budget against the built local pages before introducing third-party pixels or media. Report measured scores rather than claiming field Core Web Vitals.

## Exact Files to Touch

- `apps/landing-pages/src/app/globals.css`
- `apps/landing-pages/src/app/layout.tsx`
- `tests/performance/lighthouse.mjs` (add)
- `.github/workflows/performance.yml` (add)
- `package.json`

## Concrete Acceptance Criteria

- [ ] Run all three project pages in mobile Lighthouse CI with fixed configuration and uploaded JSON evidence.
- [ ] Enforce performance >=90, accessibility >=95, CLS <=0.1 and no external font requests for the local baseline.
- [ ] Document that lab LCP is not production field data; capture actual values and browser version.
- [ ] Add npm run test:performance and fail the workflow if budgets regress.

## Verification Command

Run from the repository root after `npm ci --ignore-scripts`:

```powershell
npm run build
npm run test:performance
```

## Execution Notes

Owner: `bot-1-landing-page`. Start from the current main baseline. New test paths and scripts listed above must be implemented by this task before running their verification commands. Browser checks require `npx playwright install chromium`. Keep real failures visible and attach exact output; never use `test.skip`, `test.fixme` or weakened assertions to claim completion.
