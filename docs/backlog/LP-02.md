# LP-02: Add a consent-aware first-party experiment event adapter

## Goal / Context

Measure variant exposure and successful queueing without leaking names, phone numbers or failed submissions. The initial adapter must default to disabled and write only to a test-injected sink.

## Exact Files to Touch

- `apps/landing-pages/src/components/LeadForm.tsx`
- `apps/landing-pages/src/lib/analytics.ts` (add)
- `tests/unit/analytics.test.ts` (add)

## Concrete Acceptance Criteria

- [ ] Define typed exposure and lead_queued events with projectId, variant and event ID only.
- [ ] No analytics network request occurs before explicit analytics consent; form processing consent remains separate.
- [ ] A retry cannot emit two conversion events for the same accepted attempt.
- [ ] Tests assert that names, phone numbers, raw request bodies and router tokens never enter analytics payloads.

## Verification Command

Run from the repository root after `npm ci --ignore-scripts`:

```powershell
npm test -- tests/unit/analytics.test.ts
npm run typecheck
```
