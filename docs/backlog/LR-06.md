# LR-06: Gate production ingress with abuse controls and data retention

## Goal / Context

Origin checking is not rate limiting. Add explicit production gates before routing real traffic or storing customer contacts.

## Exact Files to Touch

- `services/lead-router/src/app.ts`
- `services/lead-router/src/storage/retention.ts` (add)
- `apps/landing-pages/src/app/api/leads/route.ts`
- `tests/integration/abuse-controls.test.ts` (add)
- `docs/data-handling.md` (add)

## Concrete Acceptance Criteria

- [ ] Bound per-source request rates and return 429 with Retry-After; do not trust arbitrary X-Forwarded-For headers.
- [ ] Use configured public origin rather than arbitrary Host values in production.
- [ ] Provide deletion/retention jobs over durable records with deterministic time-based tests.
- [ ] Redact access logs and exceptions; demonstrate that token and contact fields never appear.
- [ ] Demo remains usable locally; deployed mode refuses known demonstration secrets and volatile storage.
