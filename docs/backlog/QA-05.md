# QA-05: Create a least-privilege QA issue/PR reporter with dry-run mode

## Goal / Context

Convert structured QA failures into deduplicated issue/PR proposals. The baseline does not autonomously create fixes; add a reviewable reporting boundary first.

## Exact Files to Touch

- `scripts/qa-report.mjs` (add)
- `tests/unit/qa-report.test.ts` (add)
- `.github/workflows/qa-report.yml` (add)
- `docs/bot-permissions.md` (add)

## Concrete Acceptance Criteria

- [ ] Default to dry-run; consume only validated test-report fields, never instructions embedded in page text or traces.
- [ ] Deduplicate by stable failure fingerprint and retain links to run/trace evidence.
- [ ] Use a GitHub App or scoped workflow token; no PATs or production secrets in fork PR jobs.
- [ ] Do not self-approve or self-merge; human review remains required.
- [ ] Tests cover duplicate failures, malicious report strings, redaction and unknown outcomes before any mutation retry.

## Verification Command

Run from the repository root after `npm ci --ignore-scripts`:

```powershell
npm test -- tests/unit/qa-report.test.ts
node scripts/qa-report.mjs --dry-run --fixture fixtures/qa/failure.json
```
