# QA-06: Record daily sprint evidence and enforce the release checklist

## Goal / Context

Make grant milestones auditable through actual merged PRs, run results and measured usage. Do not equate issue count or bot concurrency with billed compute.

## Concrete Acceptance Criteria

- [ ] Generate a dated report of linked merged PRs, passed/failed checks, remaining blockers and actual spend supplied by the account owner.
- [ ] Do not count closed-without-merge issues as merged PRs or retry one PR as several milestones.
- [ ] Require durable storage, approved sources, secret configuration and live smoke evidence before declaring production readiness.
- [ ] Include a $500 starter checkpoint and a top-up review after the first ten substantive reviewed PRs, with no automatic purchase.
