# LR-02: Replace the volatile queue with a transactional durable inbox/outbox

## Goal / Context

The demo queue loses accepted work on restart and discards successful deliveries. Introduce durable acceptance and outbox state without silently changing 202 semantics.

## Exact Files to Touch

- `services/lead-router/src/queue.ts`
- `services/lead-router/src/storage/sqlite.ts` (add)
- `services/lead-router/src/server.ts`
- `services/lead-router/migrations/001-inbox-outbox.sql` (add)
- `tests/integration/durable-queue.test.ts` (add)

## Concrete Acceptance Criteria

- [ ] Commit validated inbound event and unique source/idempotency key before returning 202.
- [ ] Use a unique database constraint and transactional worker claim so concurrent retries produce one logical job.
- [ ] Recover queued/leased jobs after process restart; test by closing and reopening a temporary database.
- [ ] Persist bounded attempts, backoff with jitter, next run time and dead-letter state; add a safe replay operation.
- [ ] Never remove undelivered jobs to make capacity; expose backpressure and document retention separately.
