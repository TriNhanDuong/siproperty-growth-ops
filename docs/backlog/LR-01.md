# LR-01: Retrieve Meta lead details through a permission-gated adapter

## Goal / Context

The local webhook currently verifies signatures and queues lead IDs only. Add a disabled-by-default Graph API adapter; no real Meta app subscription or access has been established.

## Exact Files to Touch

- `services/lead-router/src/adapters/meta.ts` (add)
- `services/lead-router/src/app.ts`
- `packages/contracts/src/index.ts`
- `tests/integration/meta-adapter.test.ts` (add)
- `.env.example`

## Concrete Acceptance Criteria

- [ ] Use an explicitly configured, currently supported Graph API version and allowlisted page IDs.
- [ ] Mock Graph responses for success, missing permissions, expired token, 429 and timeout; never call Meta in tests.
- [ ] Map only consented, expected fields to the internal contract; never log the access token or raw contact payload.
- [ ] Reject unapproved pages and retain stable pageId:leadId idempotency across retries.
- [ ] Document the live permission/app-review prerequisites and keep the default fixture path operational.
